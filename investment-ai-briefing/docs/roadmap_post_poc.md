# 제출 이후 계획: PoC 제출 버전과 실제 운영 버전

그내종은 과제 제출로 끝나는 프로젝트가 아니라, 작성자가 매일 아침 실제로 쓸 서비스다. 그래서 두 버전을 나눠 관리한다.

| | PoC 제출 버전 (이 저장소의 현재 상태) | 실제 운영 버전 (제출 이후) |
|---|---|---|
| 목적 | 개선 지점을 찾고 만들 가치가 있는지 검증 | 매일 오전에 쓰는 서비스 |
| 프로필 | 공개 데모는 가상 프로필 | 작성자의 실제 프로필(비공개) |
| 실행 | 로컬에서 `--data demo` 서버 | 실제 데이터 서버, 매일 자동 실행 |
| 비용 | 추가 비용 없음 | **추가 비용 없음** ([비용 원칙](cost_principles.md)) |

## 1. 지금 구현된 것과 아직 아닌 것 (2026-11-18)

| 기능 | 상태 | 검증 범위 |

| 미국 종목 전용 뉴스 수집, SEC 공시 | **미구현** | 등록은 되지만 분석은 기존 수집 범위 안에서만 |

## 2. 실제 운영 버전 후속 개발 항목

각 항목은 [비용 원칙](cost_principles.md)을 먼저 적용한다. 무료로 어려우면 억지로 만들지 않고 대안을 쓴다.

| # | 항목 | 비용 관점의 제약과 대안 |
|---|---|---|
| 1 | 실제 로그인·접근 권한 관리 | 외부에 공개할 때만 필요하다. 로컬 단독 사용이면 만들지 않아도 된다. 설계: [auth_design.md](auth_design.md) |
| 2 | 외부 접속 가능한 웹사이트 배포 | 인증 전에는 실제 개인 데이터로 공개하지 않는다. 무료 호스팅의 한도·약관은 아직 확인하지 않았다. 대안: 같은 와이파이, 또는 결과 파일을 개인 저장 공간으로 복사 |
| 3 | 아이폰 음성 브리핑 재생 | 대안 1순위는 이미 쓰는 개인 저장 공간(iCloud 폴더 등)에 MP3를 복사하는 것([delivery.md](delivery.md)). 개인 팟캐스트 피드는 호스팅이 필요해 무료 가능 여부 확인 후 결정 |
| 4 | 매일 07:35 뉴스 수집 마감과 자동 실행 | 맥 `launchd`(무료, 맥이 켜져 있어야 함). 클라우드 예약 실행은 하지 않는다 |
| 5 | 10~15분 길이 음성 | 구현했다(v4). 길수록 구독 사용량이 늘어, 구독 한도를 보며 조절한다 |
| 6 | 미국·한국 주요 거시지표 반영과 공식 데이터 연동 | 지금은 수집된 뉴스에서 지표 발표 기사를 식별한다. 공식 통계 연동은 무료 공개 데이터 후보의 이용 조건과 키 발급을 **확인한 뒤** 결정한다 |
| 7 | 브리핑 생성 완료·실패 알림 | 맥 알림 등 추가 비용이 없는 방식만 사용 |
| 8 | 음성 대본과 검증·수정 기록 전달 | 대본(`script.md`)과 검증 기록(`factcheck.md`)이 이미 파일로 남는다. 매일 요약해 전달하는 방식은 미정 |
| 9 | 실제 종목 검색 데이터 설정 | 무료 공식 목록(OpenDART, SEC)을 로컬에서 내려받는다. 아래 3절 |
| 10 | 집중 분석 효과 검증 | 설정 전후를 같은 후보로 비교한다. AI 호출이 필요해 구독 사용량에 여유가 있을 때 한다 |
| 11 | 미국 주식 뉴스와 SEC 공시 연동 | SEC 공개 데이터는 무료이고 식별 가능한 User-Agent가 필요하다. 미국 종목 전용 뉴스는 무료로 쓸 수 있는 소스부터 확인 |
| 12 | 개인 투자 데이터 영구 저장·백업 | 로컬 파일 저장을 유지하고 이미 가진 저장 공간으로 백업한다. 유료 데이터베이스는 쓰지 않는다 |
| 13 | 운영 비용·AI 사용량 관리 | 실행마다 `run.json`에 환산 비용을 남긴다(청구액 아님). 구독 사용량은 계정 화면에서 확인 |

## 3. 종목 목록을 직접 내려받는 방법 (제출 이후 설정)

환경변수 이름만 적는다. **실제 키와 연락처는 `.env`에만 넣고 저장소에 올리지 않는다.**

| 환경변수 | 용도 | 어디서 |
|---|---|---|
| `DART_API_KEY` | 한국 상장사 목록(OpenDART) | opendart.fss.or.kr에서 무료 발급 |
| `SEC_USER_AGENT` | 미국 종목 목록(SEC). SEC는 연락처가 담긴 식별 문자열을 요구한다 (예: `앱이름 연락처`) | 직접 정한 문자열 |

`.env`(`.env.example` 참고)에 두 값을 넣은 뒤 실행한다. 한국 목록은 시장 구분을 위해 호출이 수천 건 나가며 중간에 멈춰도 이어서 받는다.

```bash
.venv/bin/python -m app.update_symbols
```

한쪽만 받으려면 `--kr` 또는 `--us`를 붙인다. 결과는 `data/symbols/`(공개 저장소에서 제외)에 저장되고, 출처와 갱신일은 같은 폴더의 `meta.json`에 기록된다. 갱신은 월 1회 정도면 충분하다.

**이용 조건:** SEC는 식별 가능한 User-Agent와 초당 10건 이하를 요구한다. OpenDART의 호출 한도·재배포 조건과 SEC 데이터의 재배포 조건은 확인하지 못했다. 그래서 목록은 공개 저장소에 포함하지 않고 로컬에서 내려받아 쓴다.

## 4. 2차·3차 개발 항목 (프로필 화면)
- **2차:** 집중 분석 실제 효과 검증, 실제 종목 목록 설정(위 3절)
- **3차:**
  - AI 키워드 추천: 투자 이유로 관련 키워드를 추천하되 사용자가 고른 것만 반영
  - 투자 이유 변경 이력: 언제 어떻게 바꿨는지 보존
  - 종목별 브리핑 모아보기: 별도 메뉴 없이 기존 '브리핑 모음' 안의 종목별 필터로
- **하지 않을 기능:** 매수가·목표가 관리, 수익률 계산, 실시간 주가 대시보드, 매수·매도 추천, 커뮤니티·댓글, 투자 성향 테스트

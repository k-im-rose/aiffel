# 로그인과 다중 사용자 설계 (후속 개발)

그내종은 사용자의 보유 종목, 관심 종목, 투자 논리, 개인 메모로 동작하는 개인화 서비스다. 그래서 여러 사람이 쓰려면 사용자별 로그인과 데이터 분리가 꼭 필요하다.

## 1. 현재 구현 범위와 향후 구현 범위

| 항목 | 지금 (MVP) | 향후 |
|---|---|---|
| 로그인·회원가입 | **화면 시안만** (`/login`). 입력칸·버튼이 비활성화되어 있고 어떤 값도 보내지 않는다 | 이메일 로그인 + 소셜 로그인(Apple·Google·카카오) |
| 사용자 구분 | 없음. 이 컴퓨터의 사용자 한 명 | 사용자 id로 모든 데이터를 나눈다 |
| 서버 접근 | 기본 127.0.0.1에서만 열림. `--host 0.0.0.0`은 집 안 와이파이 시험용 | HTTPS, 세션 쿠키(HttpOnly·Secure·SameSite) |
| 데이터 저장 | `userdata/*.json` 파일 (`JsonStore`) | DB, 모든 행에 `user_id` |
| 브리핑 | `outputs/<run_id>/` (한 사용자) | `briefings/<user_id>/<run_id>/`, 사용자 프로필마다 생성 |
| 계정 설정 | 자리와 안내 문구만 (마이페이지) | 비밀번호 변경, 로그인 수단 연결, 데이터 내보내기·삭제, 탈퇴 |

**원칙: 인증과 사용자별 접근 권한이 완성되기 전에는 실제 개인 데이터를 담은 서비스를 공개 배포하지 않는다.** 공개 시연은 가상 데모 프로필(`--data demo`)로만 한다.

## 2. 흐름

```
회원가입 (이메일 인증 또는 소셜) → 최초 투자 프로필 설정 (/onboarding) → 메인 (/)
로그인 → 프로필에 종목이 있으면 메인, 없으면 최초 설정
```

최초 설정 화면과 메인으로의 이동 규칙(프로필에 종목이 없으면 `/onboarding`)은 지금도 동작한다. 로그인 단계만 앞에 붙이면 된다.

## 3. 데이터 분리 설계

| 데이터 | 지금 위치 | 사용자별로 바꿀 위치 | 접근 규칙 |
|---|---|---|---|
| 투자 프로필 | `userdata/profile.json` | `profiles` 테이블 (`user_id` 1:1) | 본인만 읽기·쓰기 |
| 메모 | `userdata/memos.json` | `memos` (`user_id`, date) | 본인만 |
| 점검 목록 | `userdata/checks.json` | `checks` (`user_id`) | 본인만 |
| 브리핑 (briefing.json, MP3) | `outputs/<run_id>/` | 사용자별 폴더 또는 객체 저장소 경로 | 본인만. MP3 주소는 추측할 수 없는 서명 URL |
| 기사 원본·후보 | `outputs/<run_id>/candidates*.json` | 공용 수집 결과 + 사용자별 판정 결과 | 화면으로 내보내지 않음 (지금과 같음) |

- **다른 사용자 데이터 접근 차단:** API는 요청의 세션에서 `user_id`를 얻고, 모든 조회·수정에 그 `user_id` 조건을 건다. 주소의 id(`/api/memos/{id}`, `/report/{run_id}`)만으로는 다른 사람 데이터에 닿지 않게 한다.
- **API 모양은 유지:** 지금의 경로(`/api/profile`, `/api/memos`, `/api/checks`, `/api/briefings`)와 JSON 모양을 그대로 쓰고, 서버 안에서 `JsonStore`를 사용자별 저장소로 바꾼다. 화면 코드는 바꾸지 않아도 된다.
- **파이프라인:** 수집은 하루 한 번 공용으로, 판정·편집·대본·음성은 사용자 프로필마다 실행한다. 비용이 사용자 수에 비례하므로 배포 전에 비용 상한을 정한다.

## 4. 단계

1. **(완료)** 화면 구조 분리: 메인, 일일 보고서, 마이페이지, 최초 설정, 로그인 시안.
2. 저장소 계층을 사용자 id를 받는 형태로 바꾼다 (`JsonStore(user_id)` → DB).
3. 인증: 관리형 인증 서비스 또는 검증된 라이브러리를 쓴다. 비밀번호를 직접 저장·검증하는 코드는 만들지 않는다.
4. HTTPS 배포와 MP3 객체 저장소, 서버 예약 실행.
5. 개인정보 처리: 수집 항목 고지, 데이터 내보내기·삭제, 탈퇴 시 브리핑·메모 삭제.
6. 실제 개인 데이터로 공개 운영은 1~5와 보안 점검을 마친 뒤에만 한다.

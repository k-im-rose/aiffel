## 2. 왜 자동 검증을 통과했나 (원인)

1. **원문이 원문이 아니었다.** 원문 대조 단계는 한국경제 기사 페이지에서 기자 본문 대신 언론사가 붙인 **"AI 기사요약" 상자**를 읽었다. 3번의 "안전자산 선호" 문장이 바로 그 상자의 문장이다.
   - 매일경제에서는 기사 옆의 AI 종목 카드를 본문으로 읽은 경우도 있었다.
   - 자동 요약을 원문으로 쓰는 바람에 "원문 대조로 확인"이라는 표시가 잘못된 근거에 붙었다.
2. **출처 번호의 존재만 봤다.** 사실 검증은 대사에 붙은 출처의 제목·요약을 근거로 판정했다.
   - 1번의 숫자는 검색 결과 요약에 있었다. 그래서 "근거와 일치"로 통과했다.
   - 정작 그 주소에서 읽히는 본문에 있는지는 보지 않았다.
3. **편집 단계의 결합 오류.** 편집자가 요약 속 에코프로비엠 문장 때문에 롯데칠성 기사를 ESS 이야기에 묶었다. 그 뒤 그 기사의 롯데칠성·한국전력 사실까지 ESS 이야기의 "확인된 사실"로 웹에 표시됐다.
4. **오류가 웹 보조 내용으로 번졌다.** 웹 데이터 단계가 편집자 해석을 그대로 받아, 이야기 제목("에코프로비엠 4분기 눈높이는 급락")과 AI 추천에도 같은 확인 안 된 사실이 들어갔다.

## 5. 남은 한계
- **"중대 오류 0건"의 의미:** 출처(제목·요약·읽히는 원문)와 어긋난 주장을 찾지 못했다는 뜻이다. 출처 기사 자체가 틀렸는지, 공식 통계·공시와 맞는지는 아직 자동으로 확인하지 않는다.
- **유료 기사:** 공개된 일부만 읽는다. 그 뒷부분에만 있는 사실은 확인되지 않은 것으로 처리되어 방송에서 빠질 수 있다.
- **결정적 일치 검사의 범위:** 숫자와 등록 기업명만 본다. 숫자가 없는 인과·관계 주장은 LLM 검증에 의존한다.
- **실제 프로필 브리핑:** 같은 원문 추출 오류의 영향을 받았다. 비공개 브리핑도 고친 기준으로 다시 만들어야 한다.
- **비교 수치의 신뢰도:** 이전에 README에 적은 원문 대조 수치(실제 프로필 07:35 테스트의 원문 확인 18/19 등)는 원문 추출 오류를 고치기 전에 측정한 것이다.

## 6. 추가 기록: 같은 날 두 번째 검토 (위 1~5절은 처음 기록 그대로 둔다)

### 6-1. 원문 대조 결과가 다른 이야기에 붙음 (v2 웹 데이터)
- **무엇이 틀렸나:** v2 웹 보고서의 5번 이야기("알테오젠, 월 1회 비만치료제 후보 동물실험")에 미·중·러 정상회담의 확인된 사실이, 6번 이야기("미·중·러 첫 3자 정상회담")에 코픽스의 확인된 사실이 붙었다. 7번 이야기(코픽스)에는 원문 대조 사실이 없었다. "확인 불가" 칸도 다른 이야기의 것이었다.
- **어떻게 찾았나:** 일일 보고서 화면을 새로 만들고 처음부터 끝까지 읽다가 발견했다.
- **원인:** 원문 대조는 중요한 이야기만 한다(7개 중 1·2·3·4·6·7번). 모델에게 "이야기 6", "이야기 7"이라고 번호를 붙여 넘겼지만, 모델은 결과에 번호를 1부터 차례로 다시 매겨 5·6으로 돌려줬다. 코드는 돌려받은 번호를 확인하지 않고 그대로 이야기에 붙였다.
- **영향 범위:**
  - 대본과 음성: 영향 없음. 사실 대사는 각자 붙은 출처 기사로 따로 검증되었다.
  - 웹 보고서: 5·6·7번 이야기의 '확인된 사실'과 '확인 불가'가 틀렸다. 근거 기사 링크는 각 이야기의 것이어서, 사실과 출처가 서로 맞지 않았다.
  - 다른 실행: 같은 방법으로 점검한 결과, 첫 데모(`20261117`)와 실제 프로필 브리핑 두 개는 번호가 맞게 붙어 있었다. 실패는 v2에서만 나타났다.
- **고친 것:** 모델이 돌려준 번호를 믿지 않는다. 대조 결과의 근거 기사(`source_ids`)가 모두 그 이야기의 기사일 때만 붙이고, 번호가 어긋나면 근거 기사로 맞는 이야기를 찾는다(`corroborate.attach`). 웹 데이터 단계에서도 이야기의 기사가 아닌 근거의 사실은 버린다(`export_web`). 다시 붙인 기록은 `run.json`의 `corroborate.mapping`에 남는다.
- **v2는 고치지 않고 보존했다.** 고친 결과는 v3다.

### 6-2. 맞춤법 오류가 대본과 음성에 남음
- **무엇이 틀렸나:** 해석 대사 "할부·금융 비중이 어느지"가 v2 대본과 음성에 그대로 들어갔다. 맞는 표현은 "어느 정도인지"다.
- **원인:** 사실 검증은 사실 주장만 본다. 맞춤법은 어느 단계도 보지 않는다.
- **고친 것:** v3에서 그 대사만 고치고 음성을 다시 만들었다. 사실 주장과 출처는 바뀌지 않아 출처 대조는 다시 돌리지 않았다.
- **남은 한계:** 맞춤법 자동 점검은 아직 없다.

### 6-3. "중대 오류 0건"의 표현
- **문제:** 웹 화면에 "사실 검증: 주장 23개 중 중대 오류 0건"이라고 적어, 독립적인 사실 검증을 마친 것처럼 읽힐 수 있었다.
- **고친 것:**
  - 표시를 "출처 대조"로 바꾸고, 같은 자리에 범위를 적었다: 출처 기사 대조 결과이며 독립적인 사실 검증이 아니고, 기업 공시·공식 통계와는 대조하지 않았다.
  - 사실 문장마다 근거 수준을 붙였다: 기자 본문에서 확인 / 공개된 일부 본문에서 확인 / 원문 확인 불가·제목·요약 기준.
  - 출처에서 확인할 수 없는 주장은 '확인 불가'로 분류해 대본과 확인된 사실에서 빼고, 이야기마다 '확인 불가' 칸에 따로 보여 준다. 판정 이름도 '근거 없음(unsupported)' 대신 '확인 불가 (출처에 없음)'로 쓴다.

### 6-4. 실제 프로필 브리핑 재생성 (비공개, 집계만)
5절에서 남은 일로 적은 실제 프로필 브리핑을 고친 기준으로 다시 만들었다. 이전 브리핑은 그대로 두었다.
- **결과:** 이야기 11개, 원문 확인 26/27건, 13분 2초. 최종 사실 주장 38개 중 출처와 어긋난 주장 0건.
- **새 검사가 실제로 잡은 것:** 1회차에 출처 불일치 1건, 출처에 없는 인과 1건(모두 중대), 2회차에 경미 1건. 모두 고친 뒤 재검증했다.
- **새 한계:** 마지막 일치 검사가 "8억 2,500만 주"를 "825 million"과 같은 값으로 환산하지 못해, 맞는 문장의 일부를 뺐다(과잉 차단). 틀린 내용이 들어가지는 않았지만 정보가 줄었다. 복합 수 표기 환산은 후속 과제다.
- **기록 보완:** 이 실행 도중 검증 코드를 고쳐, 마지막 웹 데이터 단계만 실패했다. 그 단계만 다시 실행했다.
- **파일 이름 변경:** 1~5절의 `web/app.js`는 화면 구조를 나누면서 `web/v1_single_page/app.js`로 옮겼고, 같은 기능은 `web/report.js`에 있다.

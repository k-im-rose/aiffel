03-04 선택 과제 B · OCR 표 문서화 결과 해설

글자를 읽었다고 표가 된 것은 아니다

B는 그림으로 된 표를 검색·복사할 수 있는 표로 바꾸는 과제입니다. 핵심은 OCR이 읽은 값이 원본의 어느 자리에서 왔는지를 끝까지 연결해 두고, 틀린 곳을 사람이 근거와 함께 고치는 것입니다.

교안의 출발점

"AI가 잘못 읽었다"는 두 가지 다른 문제다

글자를 잘못 읽음 (인식)

계약서의 32,000,000을 3,200,000으로 읽은 경우입니다. 문자 인식 단계를 봐야 합니다.

짝을 잘못 붙임 (구조)

금액은 맞게 읽었는데 아래 행의 부가세와 짝을 바꾼 경우입니다. 항목과 값의 관계를 봐야 합니다.

이번 표에서 나온 오류는 앞쪽, 글자를 잘못 읽은 문제였습니다. 행과 열의 짝은 22칸 모두 맞았습니다.

1/4

OCR의 네 작업과 이번 실행

교안

전처리 → 검출 → 인식 → 레이아웃 분석으로 나누어 두면, 결과가 이상할 때 입력·영역·문자열·구조 중 어디서 어긋났는지 짚을 수 있습니다. 앞 단계의 문제가 뒤 결과로 이어지는 것을 오류 전파라고 합니다.

전처리기울기·대비·해상도 조정과제에서 200 dpi로 잘라 준 이미지를 그대로 씀. 방향 보정 모듈은 끔.
검출 ← 오류 시작글자가 있는 영역 찾기영역 41개를 찾음. 그런데 각주 위첨자와 숫자를 한 영역으로 묶음.
인식 ← 오류 드러남잘라낸 영역을 문자열로묶인 영역의 위첨자 ¹, ²를 보통 숫자 1, 2로 읽음 → 2칸 틀림.
레이아웃 분석조각을 행·열로 연결x 좌표(670, 860)로 열을, y 중심으로 행을 나눔. 22칸 짝은 모두 맞음.

틀린 값은 인식 결과에서 보였지만, 시작은 위첨자를 숫자와 같은 줄로 묶은 검출 단계였습니다. 교안의 오류 전파가 실제로 일어난 모습입니다.

2/4

점수는 틀린 칸을 알려 주지 않았다

A 과제와 같은 교훈

confidence는 후보를 추리는 데 쓰는 모델의 점수일 뿐, 맞을 확률이 아닙니다. OCR 인식 점수도 마찬가지입니다.

숫자 21개의 인식 점수를 한 줄에 놓았습니다. "점수가 이 값보다 낮은 칸만 사람이 다시 본다"고 정하면 무엇을 잡고 무엇을 놓치는지 움직여 보세요.

이 점수 미만만 검토0.970
맞게 읽은 숫자틀리게 읽은 숫자세로선 왼쪽 = 사람이 검토

필리핀 칸(0.989)은 맞게 읽은 두 칸(0.962, 0.964)보다 점수가 높습니다. 점수 기준만으로는 틀린 칸 두 개를 모두 잡으려면 맞는 칸까지 같이 봐야 합니다.

3/4

계산으로 오류를 찾고, 원본으로 확인한다

교안

계약서의 값은 단가와 수량을 곱하거나 날짜 범위를 확인해 오류를 찾아볼 수 있습니다. 계산이 맞는 값도 원본과 대조해야 검토가 마무리됩니다.

이 표는 하위 지역 8곳의 인구를 더하면 Outlying possessions의 값과 같아야 합니다.

하위 지역인구

원시값의 합은 19,343,221로 1,020만 명이 남습니다. 필리핀 앞에 붙은 1(10,000,000)과 파나마 앞에 붙은 2(200,000)를 더한 값과 정확히 같습니다. 검산이 "어딘가 틀렸다"를 알려 주고, 원본 확대가 "어디가 왜"를 알려 줍니다.

4/4

원시 결과와 사람의 수정을 따로 남긴다

교안

보기 좋게 정리한 파일은 원시 결과와 따로 두고, 수정 전 내용과 이유를 기록합니다. 원본 페이지, PNG, 글자 영역 좌표, 인식 문자열, 최종 구조를 연결해 보존하면 오류가 시작된 곳을 찾을 수 있습니다.

// review.json: 사람이 원본과 대조해 적은 수정 (스크립트는 자동으로 고치지 않음) { "row": "Philippine Islands", "col": "pop", "raw": "17,635,426", // OCR이 읽은 그대로 "value": 7635426, // 원본 대조 후 "footnote": "Population in 1903.", "reason": "위첨자 1(각주 번호)을 숫자로 붙여 읽음 …" }
  • 다음에 OCR을 다시 돌렸을 때 원시값이 "17,635,426"이 아니면 스크립트가 멈춥니다. 예전 판단을 새 결과에 잘못 덮어쓰지 않게 하려는 장치입니다.
  • 해외 복무 군인의 면적 칸은 원본에 점선만 있어 0이 아니라 빈칸으로 두었습니다. 추측으로 채우지 않는다는 교안의 원칙입니다.
  • 필리핀(1903년)과 파나마 운하 지대(1912년)의 인구는 1910년 값이 아닌데도 원본 합계에 더해져 있습니다. 이 점을 각주 열과 문서에 함께 남겼습니다.
정리

한 줄로 정리하면

점수 0.989로 자신 있게 틀린 숫자를, 표 안의 합계 검산이 먼저 의심하게 만들고 원본 확대가 확인했습니다. 그 과정을 review.json에 남겨 다음 검토자도 같은 자리로 돌아갈 수 있게 했습니다.

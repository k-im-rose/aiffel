# PRD - 아, 그게 뭐더라?

> 헷갈리는 용어를 찾아보고, 내 말로 설명할 수 있을 때까지 체크하는 용어 사전 겸 암기장

## 1. 한 문장 설명

**누구나 헷갈리는 용어를 내 말로 설명해 보며 익히는 용어 사전 겸 암기장**

이름을 지은 이유:
> 분명 봤는데 생각이 안 날 때, 누구나 하는 그 말.
> 그 말이 나오는 순간 바로 열어 보라고 지은 이름이에요.
>
> 줄여서 **아그뭐**.

첫 용어장과 첫 사용자는 AI 개발 입문자(나)다. 이 퀘스트에서는 AI 개발 용어로 시작하고(처음 20개 → 교육자료 01-04, 02-01~02-07 전체 144개. 섹션은 용어가 처음 나온 자료 기준), 다른 주제의 용어장은 다음 단계에서 사용자가 직접 만든다 (8. 로드맵).

도메인 연결 문장 (평가용):
> 내 전문 분야의 이 불편을 — AI 에이전트 개발을 배우며 하네스, MCP, RLS 같은 용어를 읽고 넘어갔다가, 실습에서 다시 마주치면 뜻도 설명도 출처도 떠오르지 않는 불편을 — 내 말로 설명해야 '안다'고 체크되는 용어장으로 풀어 봅니다.

## 2. 서비스 개요

- **타겟 사용자:** 모두연 바이브 코딩·AI 에이전트 과정을 듣는 AI 개발 입문자 (첫 사용자는 나, 다음 단계에서 동기들)
- **사용 순간:** ① 강의를 들은 뒤 새 용어를 정리할 때 ② 실습·작업 중 헷갈리는 용어를 사전처럼 검색할 때 ③ 다음 수업 전에 헷갈리는 용어를 복습할 때
- **해결할 문제:** AI 개발을 막 배우는 초보자가, 강의에서 본 용어를 제대로 이해하지 못한 채 넘어가 실습 때마다 다시 찾아본다.
- **내가 막히는 네 가지 지점**

| 내가 막히는 지점 | 이 앱의 대응 | 버전 |
|---|---|---|
| 뜻을 잊어버린다 | 용어마다 내가 쓴 설명이 남아서 바로 다시 본다 | 첫 조각 |
| 설명을 못 한다 | 내 말로 설명을 써야 '마치기'로 체크된다 | 첫 조각 |
| 어디서 봤는지 못 찾는다 | 용어마다 출처(자료 번호·섹션)가 붙어 있다 | 첫 조각 |
| 비슷한 용어가 헷갈린다 | 짝 용어(인증↔인가 등)를 나란히 비교해 본다 | 다음 단계 (Should) |

- **용어 범위:** 교육자료 01-01 ~ 02-07에서 뽑은 용어. 처음 20개(`용어집.md`의 "시작용 20개")로 시작해 144개로 확장. 따로 '핵심' 묶음은 두지 않고 처음 나온 자료 섹션에 넣는다

## 3. 핵심 흐름 하나

**용어 목록 보기 → 용어 하나를 골라 내 말로 설명 쓰기 → '마치기' → 진행률이 올라간다**

예시:
1. 목록에서 `하네스` (상태: 알아보기, 출처: 02-06)를 누른다.
2. 자료의 한 줄 뜻을 참고해서 내 설명을 쓴다: `AI 모델이 실제로 일하게 해 주는 작업 환경. 파일 읽기, 명령 실행, 승인 같은 걸 담당한다.`
3. '마치기'를 누른다 → 진행률이 `20개 중 1개`에서 `2개`로 오른다.
4. 새로고침해도 내 설명과 상태가 그대로 남아 있다.

## 4. 범위 (MoSCoW)

### 꼭 (Must) - 이번에 만든다
1. **용어 목록:** 시작용 20개를 미리 넣어 둔다. 용어마다 영문, 자료의 한 줄 뜻, 출처, 내 상태가 보인다.
2. **내 말로 설명하기:** 용어를 골라 설명을 쓰고 상태를 **알아보기 / 다시보기 / 마치기** 중 하나로 바꾼다.
3. **찾기와 진행률:** 작업 중 헷갈리는 용어를 사전처럼 검색하고(용어·영문·한 줄 뜻·내 설명에서, 초성으로도 찾기), 상태로도 걸러 본다("다시보기"만). "마치기 n / 20"을 본다. 내 설명과 상태는 자동 저장되고 새로고침해도 남는다.

### 있으면 좋음 (Should) - 첫 조각이 돌아간 뒤
- **헷갈리는 짝 비교:** 인증↔인가, 프론트엔드↔백엔드처럼 짝 용어를 나란히 보기
- **복습 모드:** '다시보기' 용어를 한 장씩 보고, 내 설명을 가린 채 떠올린 뒤 펼쳐서 확인
- ~~**사전 범위 넓히기**~~ → 완료 (2026-11-04): 02-01~02-07에서 실전 용어 124개 추가, 중복 합침, 자료별 섹션과 섹션별 진행률, 쉬운 설명(비유)·예시를 정의 아래에 표시

- ~~**구글 로그인**~~ → 완료 (2026-11-04, Main Quest 확장): 로그인하면 휴대폰·PC에서 같은 기록. 로그인 전 기록은 로그인할 때 계정으로 옮김. 로그인 없이도 지금처럼 쓸 수 있음

### 나중에 (Could)
- 용어 직접 추가 (새 강의 용어)

### 지금은 안 함 (Won't) - 일부러 뺀다
1. 동기끼리 기록 공유 (로그인은 붙였지만 기록은 각자만 본다)
2. AI가 내 설명을 채점하거나 피드백하기
3. 교육자료 PDF에서 용어 자동 추출
4. 퀴즈 자동 생성
5. 복습 알림, 간격 반복 일정
6. 용어 뜻을 AI가 자동으로 작성하기

## 4-1. 화면 구성

| 화면 | 무엇을 하나 | 들어가는 것 |
|---|---|---|
| **① 홈 · 용어 목록** | 찾고, 고르고, 진도를 본다 | 맨 위 로그인(Google로 로그인 / 로그인한 이메일·로그아웃), 머리말(제목·안내·상태 설명), 검색창, 진행률(`마치기 n / 144`), 상태 필터(전체·알아보기·다시보기·마치기), 보기 방식(자료별·전체 목록), 자료별 섹션(펼치기·접기, 섹션 진도), 용어 줄(번호·이름·상태 라벨) |
| **② 용어 카드 (상세)** | 읽고, 나의 언어로 쓰고, 상태를 고른다 | 번호·출처·난이도, 큰 영어 이름·한글 이름·영문 풀네임, DEFINITION·쉽게 말하면·예를 들면, MY NOTE(자동 저장, 기록 지우기), 상태 버튼 3개, 연결할 용어 |

- **PC:** ①과 ②가 한 화면에 나란히 (왼쪽 목록, 오른쪽 카드). 홈에서는 카드 자리를 비운다
- **휴대폰:** ① → 누르면 ② → 뒤로 가기·`← 목록`으로 ①
- **주소:** 카드마다 `#용어id` 주소가 있어서 링크로 보낼 수 있다
- **상태 표시:** 불러오는 중, 서버 연결 실패(다시 시도), 저장 중·저장됨·저장 실패

## 4-2. 데이터 구조

DB 표는 세 개. 용어 사전은 모두가 같이 쓰고, 내 기록은 사람마다 따로다. (실제 SQL: `supabase/schema.sql`)

**sections** — 교육자료 묶음

| 칸 | 뜻 | 예 |
|---|---|---|
| `id` | 자료 번호 (기본 키) | `02-04` |
| `title` | 섹션 이름 | `백엔드와 데이터베이스` |

**terms** — 용어 사전 (공용)

| 칸 | 뜻 | 예 |
|---|---|---|
| `id` | 용어 ID (기본 키, 바꾸지 않음) | `rls` |
| `section_id` | 처음 나온 자료 → sections.id | `02-04` |
| `position` | 번호 (WORD 001…) | `94` |
| `term` · `ko` · `full_name` | 영어 이름 · 한글 이름 · 약어 풀네임 | `RLS` · `행 수준 보안` · `Row Level Security` |
| `src` | 나온 자료 전부 | `02-04 · 02-07` |
| `level` | 난이도 | `실전` |
| `def` · `easy` · `ex` | 교육자료 뜻 · 쉬운 비유 · 실제 장면 | |
| `related` | 연결할 용어 ID 목록 | `{auth, database}` |

**notes** — 내 기록 (사람마다 따로)

| 칸 | 뜻 | 규칙 |
|---|---|---|
| `owner_id` | 기록 주인. 로그인 전 `device:<브라우저마다 만든 UUID>`, 구글 로그인 후 `user:<계정 ID>` | 기본 키 ①. 두 형식만 허용 |
| `term_id` | 어떤 용어 → terms.id | 기본 키 ② |
| `mine` | 내 설명 | 2000자까지 |
| `status` | 0 알아보기 · 1 다시보기 · 2 마치기 | 0·1·2만. **2는 mine이 비어 있으면 안 됨** |
| `updated_at` | 마지막 저장 시각 | |

## 4-3. API

| 메서드 | 주소 | 하는 일 (CRUD) |
|---|---|---|
| `GET` | `/api/terms` | 섹션과 용어 전체 조회 (Read) |
| `GET` | `/api/notes` | 내 기록 조회 (Read) |
| `PUT` | `/api/notes/:termId` | 내 설명·상태 저장 (Create/Update). 규칙에 어긋나면 400 |
| `DELETE` | `/api/notes/:termId` | 그 용어의 내 기록 지우기 (Delete) |
| `GET` | `/api/health` | 서버 상태 확인 (배포 점검용) |
| `GET` | `/api/auth/me` | 지금 로그인한 사람 (없으면 `user: null`) |
| `GET` | `/api/auth/google` → `/api/auth/callback` | 구글 로그인 시작 → 돌아와서 세션을 쿠키에 담기 |
| `POST` | `/api/notes/merge` | 로그인 직후, 이 기기의 기록을 계정으로 옮기기 |
| `POST` | `/api/auth/logout` | 로그아웃 |

- 내 기록 API는 로그인했으면 계정으로, 아니면 `X-Device-Id` 헤더(UUID)로 주인을 정한다
- 로그인 토큰은 브라우저 JS가 읽을 수 없는 httpOnly 쿠키에만 둔다
- 화면에서 막는 규칙(설명 없이 '마치기' 금지)을 서버와 DB에서도 한 번 더 막는다

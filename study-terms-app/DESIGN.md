# DESIGN - 노랑 메모지 스타일

> 화면을 만들 때 따르는 디자인 기준입니다. 기능과 범위는 PRD.md를 따릅니다.

## 분위기

건축 학교 강연 포스터처럼 **노랑·흰색·검정**만 쓰는 대담한 에디토리얼 무드.
큰 고딕 글자, 노란 메모지 블록과 작은 검정 라벨이 핵심이다. 글꼴은 고딕 하나로 일관되게 쓴다.
그라데이션, 그림자, 둥근 알약 모양, 일러스트는 쓰지 않는다. 모서리는 각지게.

참고 무드: USC School of Architecture FA.18 강연 포스터 (레이아웃이 아니라 색·글자·메모지 느낌만 가져온다)

## 색

| 역할 | 값 |
|---|---|
| 페이지 배경 | 종이색 `#F5F3EE` |
| 카드 배경 | 흰색 `#FFFFFF` |
| 메모지 블록·강조 | 노랑 `#FFC629` |
| 주요 글자·선·라벨 바탕 | 검정 `#111111` |
| 보조 글자 | 회색 `#5B5B5B` |
| 배경 큰 글자 | 옅은 회색 `#E4E0D8` |

대비 확인 결과: 검정/노랑 12.0:1, 검정/종이 17.0:1, 회색/종이 6.1:1, 흰 글자/검정 18.9:1로 모두 충분.
**노랑은 배경 전용**이다. 노랑/종이는 1.4:1이라 노란 글자나 노란 선만으로 정보를 전하지 않는다.

## 글자

- **Pretendard 하나만** 쓴다. 영어·한글·숫자 모두 같은 고딕으로 일관되게. 이탤릭·세리프는 쓰지 않는다.
- 제목과 큰 용어는 굵게(700), 자간을 좁게. 위계는 글꼴이 아니라 크기·굵기·노랑 배경으로 만든다.
- 본문은 편안하게 읽히도록 약 18~20px, 줄 간격 넉넉하게
- 라벨(WORD, DEFINITION, MY NOTE 등): 검정 바탕에 흰 글자, 작은 대문자, 넓은 자간 — 포스터의 `LECTURE` 라벨처럼

## 화면 구성

**데스크톱:** 왼쪽에 검색과 목록, 오른쪽에 카드 한 장.
**휴대폰:** 목록 → 누르면 카드 → `← 목록`으로 돌아오기.

1. **머리말:** 검정 박스 `WHAT'S THE WORD AGAIN?` + 노란 띠 위의 한 줄 제목 `아, 그게 뭐더라?` + 오른쪽에 짧은 안내
2. **검색창:** 굵은 검정 밑줄 하나만 있는 큰 입력칸
3. **진행률:** `마치기 n / 20`과 검정 진행 막대
4. **필터:** [전체] [알아보기] [다시 보기] [마치기] — 각 개수 표시
5. **보기 방식:** [자료별로 보기] [전체 목록]. 자료별은 `핵심 20개`, `02-01 …` 섹션을 눌러 펼치고 접으며, 섹션마다 `마친 수 / 전체` 진행률을 보여 준다. 검색 중에는 섹션 없이 찾은 용어만
6. **용어 목록:** 한 줄짜리 목록. 줄마다 `번호  영어 용어  한글 이름 ···· 상태 라벨`. 고른 줄은 노랑 배경
6. **용어 카드** (흰 종이, 검정 테두리)
   1. 라벨: `WORD 006` + `출처 02-06`
   2. 제목: 아주 큰 영어 용어. 그 아랫부분에 노란 메모지가 겹쳐 놓이고(곱하기 블렌드), 메모지 안에 한글 이름과 영문 전체 이름
   3. (개념 흐름 상자는 뺐다. 무엇의 흐름인지 알기 어려워서, 아래 쉬운 설명·예시로 대신한다)
   4. 정의: 라벨 `DEFINITION`, 한 줄 뜻(PDF 기반). 그 아래 작은 회색 글씨로 `쉽게 말하면`(비유)과 `예를 들면`(실제 장면). 버튼 없이 바로 보인다. 연결할 용어·난이도는 내용이 있을 때만
   5. 내 설명: 라벨 `MY NOTE`, **줄이 그어진 노란 메모장** 모양 입력칸, 오른쪽 위에 `저장됨 ✓`
   6. 상태 버튼: [알아보기] [다시 보기] [마치기] — 버튼·목록·필터·진행률 모두 같은 이름을 쓴다
   7. 하단: `연결할 용어` 링크(누르면 그 카드로 이동)

## 상태 표시 (색과 글자를 함께)

| 상태 | 모양 |
|---|---|
| 알아보기 (처음) | 검정 테두리만 있는 라벨 |
| 다시 보기 (공부 중) | 노랑 바탕 + 검정 글자 |
| 마치기 (끝) — 목록에는 `✓ 마치기` | 검정 바탕 + 흰 글자 |

## 사용성 원칙 (편하고 쉽게)

### 1. 찾기가 제일 빨라야 한다 (사전으로 쓸 때)
- 페이지를 열면 **검색창에 바로 커서**가 있다. 다른 곳에 있을 때 `/` 키를 누르면 검색창으로 간다.
- **타이핑하는 즉시** 목록이 줄어든다. 검색 버튼을 누를 필요가 없다.
- 한글, 영어, 대소문자 구분 없이 찾는다. `mcp`, `MCP`, `연결 규격` 모두 MCP가 나온다.
- **초성 검색:** `ㅎㄴㅅ`만 쳐도 하네스가 나온다.
- 찾은 글자는 목록에서 **노란 형광펜**으로 표시해서 왜 나왔는지 보이게 한다.
- `Enter`를 누르면 첫 번째 결과 카드가 열리고, `Esc`를 누르면 검색어가 지워진다.
- 결과가 없으면 빈 화면 대신 **"용어집에 아직 없어요"**와 전체 보기 버튼을 보여 준다.

### 2. 저장 버튼 없이, 그러나 저장됐다는 건 보이게
- 내 설명은 **쓰는 대로 자동 저장**하고 `저장됨 ✓`을 보여 준다.
- 상태 버튼도 누르는 즉시 저장된다.
- 이 브라우저에서 저장이 안 되면 그 사실을 알려 준다.

### 3. 진짜로 아는지 확인하게 (공부할 때)
- '마치기'는 내 설명을 써야만 누를 수 있다. (PRD 규칙)
- 마친 용어의 내 설명을 다 지우면 '다시 보기'로 되돌리고 알려 준다.
- 다음 단계의 복습 모드에서는 자료의 한 줄 뜻을 가린 채 먼저 떠올려 쓰게 한다.

### 4. 누르기 쉽고 헷갈리지 않게
- 버튼과 목록 줄은 **최소 44px 높이**.
- 한 화면에는 카드 하나만.
- 마지막으로 본 용어와 필터를 기억해서, 다시 열면 이어서 볼 수 있게 한다.
- 키보드로 이동할 때 초점이 잘 보이게 (검정 두 줄 테두리).

참고한 자료: Baymard Institute(자동 완성), Nielsen Norman Group(Efficiency vs. Expectations), W3C WCAG 2.2(대비·터치 영역), Dunlosky 외 2013(인출 연습 효과), Hangul.js·es-hangul(초성 검색)

## 용어 하나에 필요한 내용

| 항목 | 예시 (하네스) | 누가 채우나 |
|---|---|---|
| 번호 | 006 | 미리 넣음 |
| 영어 용어 / 한글 이름 / 영문 풀네임 | Harness / 하네스 / (약어가 아니라 비움) — API라면 Application Programming Interface | 미리 넣음. 풀네임은 약어일 때만, 없으면 비워서 줄을 숨긴다 |
| 개념 흐름 3칸 (화면에는 안 보임) | 모델 → 하네스 → 에이전트 | 데이터로만 남김 |
| 한 줄 뜻 + 출처 | AI 모델이 실제로 일하도록 감싸 주는 작업 환경 / 02-06 | 미리 넣음 |
| 예시 | Claude Code — 파일을 읽고 명령을 실행하고, 위험한 작업은 승인을 받는다 | 미리 넣음 |
| 연결할 용어 2~3개 | 에이전트 / 도구 호출 | 미리 넣음 |
| 내 설명, 상태 | (사용자가 쓴다) | 사용자 |

콘텐츠 원칙: 카드 하나에 용어 하나, 한 줄 뜻은 초보자도 아는 말로, 예시는 실제 개발이나 사용 장면으로, 연결할 용어는 2~3개만.

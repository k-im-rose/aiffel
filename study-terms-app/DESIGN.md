# DESIGN - 다크 테크 "AI Field Notes" 스타일

> 3단계(화면)에서 AI에게 함께 건네줄 디자인 기준입니다. 기능과 범위는 PRD.md를 따릅니다.

## 분위기

트렌디하고 정돈된 개발자 노트. 장식은 최소로 하고 글자와 여백으로 위계를 만든다.
과한 그라데이션, 네온 효과, 그림자, 일러스트는 쓰지 않는다.

## 색

| 역할 | 값 |
|---|---|
| 카드 배경 | 짙은 녹색 `#1E3932` |
| 페이지 배경 | 카드보다 한 단계 어두운 녹색 (예: `#13241F`) |
| 주요 글자 | 크림색 `#F2F0EB` |
| 보조 글자 | 연한 녹색 `#D9E8DF` |
| 테두리 | 세이지 그린 `#4E8A6B`, 1px |
| 구분선 | 연한 녹색 `#D9E8DF`를 낮은 불투명도(약 18%)로 |
| 선택된 버튼 | 크림색 배경 + 짙은 녹색 글자 (세이지 배경 + 크림 글자는 대비 3.6:1이라 작은 글씨에 부족) |
| 입력칸 안내 문구 | 연한 녹색 65% 이상 불투명도 (50%는 대비 약 3.7:1로 흐림) |

대비 확인 결과 (배경 `#1E3932` 기준): 크림 10.9:1, 연한 녹색 9.8:1로 글자에 충분. 세이지 그린은 3.1:1이라 **테두리·구분선 전용**이고 글자색으로 쓰지 않는다.

## 글자

- 폰트: Pretendard
- 영어 용어 제목은 크게(약 62px, 좁은 화면에서는 줄어들게), 굵게, 자간을 살짝 좁게
- 한글 설명은 편안하게 읽히도록(본문 약 19px, 줄 간격 넉넉하게)
- 라벨(AI FIELD NOTES, DEFINITION, MY NOTE)은 작은 대문자에 넓은 자간

## 화면 구성 (위에서 아래로)

1. **검색창:** "용어 검색" — 용어, 영문, 한 줄 뜻, 내 설명에서 찾기
2. **필터와 진행률:** [전체] [헷갈림만] 알약 버튼, 오른쪽에 `설명 가능 n / 20`과 얇은 진행 막대
3. **용어 목록:** 한 줄짜리 목록. 줄마다 `영어 용어  한글 이름  ····  상태`. 고른 줄은 크림색 배경으로 강조. (알약 칩은 20개가 넘으면 화면을 덮어서 쓰지 않는다)
4. **용어 카드** (세로형, 최대 너비 440px, 안쪽 여백 27px, 모서리 20px)
   1. 상단: 왼쪽 `● AI FIELD NOTES`, 오른쪽 `CONCEPT / 번호`
   2. 제목: 큰 영어 용어 + 옆에 작은 한글 이름, 아래 줄에 영문 전체 이름
   3. 개념 흐름: 테두리 상자 3개를 화살표로 연결 (예: [모델] → [하네스] → [에이전트])
   4. 정의: 구분선, 라벨 `DEFINITION · 출처 02-06`, 한 줄 뜻
   5. 내 설명: 구분선, 라벨 `MY NOTE · 상태`, 입력칸, [모름] [헷갈림] [설명 가능] 알약 버튼, 규칙 위반 시 안내 문구
   6. 하단: 구분선, 왼쪽 `연결할 용어 · A / B`(누르면 그 용어 카드로 이동), 오른쪽 알약 버튼 `예시 보기 ↗`

## 동작

- **예시 보기 ↗:** 정의 영역만 `IN PRACTICE` 예시로 바뀌고, 버튼은 `정의로 돌아가기 ↙`로 바뀐다. 카드 크기와 다른 요소는 그대로.
- **연결할 용어:** 누르면 그 용어 카드로 바로 이동한다.
- 모바일 폭에서도 글자가 잘리거나 겹치지 않는다.

## 사용성 원칙 (편하고 쉽게)

무드는 다크 테크로 가되, 쓰는 방법은 아래 원칙을 따른다.

### 1. 찾기가 제일 빨라야 한다 (사전으로 쓸 때)
- 페이지를 열면 **검색창에 바로 커서**가 있다. 다른 곳에 있을 때 `/` 키를 누르면 검색창으로 간다.
- **타이핑하는 즉시** 목록이 줄어든다. 검색 버튼을 누를 필요가 없다. (찾는 대상이 정해진 검색에 즉시 결과가 잘 맞음)
- 한글, 영어, 대소문자 구분 없이 찾는다. `mcp`, `MCP`, `연결 규격` 모두 MCP가 나온다.
- **초성 검색:** `ㅎㄴㅅ`만 쳐도 하네스가 나온다.
- 찾은 글자는 목록에서 **밑줄이나 밝은 색으로 표시**해서 왜 나왔는지 보이게 한다.
- `Enter`를 누르면 첫 번째 결과 카드가 열리고, `Esc`를 누르면 검색어가 지워진다.
- 결과가 없으면 빈 화면 대신 **"용어집에 아직 없어요"**와 비슷한 용어를 보여 준다.

### 2. 저장 버튼 없이, 그러나 저장됐다는 건 보이게
- 내 설명은 **쓰는 대로 자동 저장**한다.
- 사람들은 보통 "저장 버튼을 눌러야 반영된다"고 생각하므로, 입력칸 옆에 작게 **`저장됨 ✓`**을 보여 줘서 안심시킨다.
- 상태 버튼(모름·헷갈림·설명 가능)도 누르는 즉시 저장된다.

### 3. 진짜로 아는지 확인하게 (공부할 때)
- 정답을 **보고 나서 "알았다"고 누르는 건 진짜 기억이 아니다.** 그래서 '설명 가능'은 내 설명을 써야만 누를 수 있다. (PRD 규칙)
- 다음 단계의 복습 모드에서는 **자료의 한 줄 뜻을 가린 채** 먼저 떠올려 쓰고, 그다음 펼쳐서 비교한다. 직접 떠올리는 연습이 다시 읽기보다 기억에 오래 남는다.

### 4. 누르기 쉽고 헷갈리지 않게
- 버튼과 목록 줄은 **최소 44px 높이**로 손가락으로 누르기 편하게 한다.
- 상태는 **색과 글자를 함께** 쓴다. (색만으로 구분하지 않기)
- 한 화면에는 카드 하나만. 휴대폰에서는 목록 → 누르면 카드 → 뒤로 가기로 목록 순서.
- 마지막으로 본 용어와 필터를 기억해서, 다시 열면 이어서 볼 수 있게 한다.

참고한 자료: Baymard Institute(자동 완성), Nielsen Norman Group(Efficiency vs. Expectations), W3C WCAG 2.2(대비·터치 영역), Dunlosky 외 2013(인출 연습 효과), Hangul.js·es-hangul(초성 검색)

## 용어 하나에 필요한 내용

| 항목 | 예시 (하네스) | 누가 채우나 |
|---|---|---|
| 번호 | 006 | 미리 넣음 |
| 영어 용어 / 한글 이름 / 영문 전체 | Harness / 하네스 / 에이전트 = 모델 + 하네스 | 미리 넣음 |
| 개념 흐름 3칸 | 모델 → 하네스 → 에이전트 | 미리 넣음 |
| 한 줄 뜻 + 출처 | AI 모델이 실제로 일하도록 감싸 주는 작업 환경 / 02-06 | 미리 넣음 |
| 예시 | Claude Code — 파일을 읽고 명령을 실행하고, 위험한 작업은 승인을 받는다 | 미리 넣음 |
| 연결할 용어 2~3개 | 에이전트 / 도구 호출 | 미리 넣음 |
| 내 설명, 상태 | (사용자가 쓴다) | 사용자 |

콘텐츠 원칙: 카드 하나에 용어 하나, 한 줄 뜻은 초보자도 아는 말로, 예시는 실제 개발이나 사용 장면으로, 연결할 용어는 2~3개만.

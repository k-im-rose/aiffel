# 회고 — 아, 그게 뭐더라? (Main Quest 01)

> 2026-11-03 ~ 11-04. 에이전트(Claude Code)와 대화하며 기획부터 배포까지 한 바퀴 돌고, API 서버·DB·구글 로그인까지 붙였다.
> 이 회고는 작업 기록을 바탕으로 쓴 **초안**이다. 느낀 점은 직접 고쳐 쓴다.

## 한 줄 요약

"다 만들려 하지 말고, 한 흐름이 끝까지 굴러가게." 용어를 찾고 → 읽고 → 나의 언어로 쓰고 → 마치는 흐름 하나를 배포까지 끝냈다. 그다음에 저장을 브라우저에서 서버 DB로 옮기고(버전 2), 구글 로그인으로 휴대폰·PC에서 같은 기록을 보게 넓혔다(확장).

## 1. 무엇을 잘랐나 — 가장 아까웠던 것

| 자른 것 | 아까웠던 이유 | 그래도 자른 이유 |
|---|---|---|
| **투자 주제** (뉴스·실적 자동 알림, 내 종목 영향 분석) | 실제로 가장 원하던 기능이었다 | 외부 데이터·AI 분석·알림이 모두 필요해서 첫 조각으로는 너무 컸다. "눌러서 확인할 수 있나?"를 통과하지 못했다 |
| **냉장고 재료 앱** | 불편이 가장 생생했다 | 루브릭의 도메인 연결성("내 전문 분야")에서 불리했다. 다음 과제 후보로 남겨 둠 |
| **로그인·동료와 함께 쓰기** | 동료들이 각자 수준에 맞게 쓰면 좋겠다 | 혼자 쓰는 첫 조각에는 과하다. 로드맵의 다음 단계로 → **확장 과제로 구글 로그인은 붙였다** (기록 공유는 여전히 안 함) |
| **AI가 내 설명 채점하기, 오늘의 용어** | 공부 앱다운 기능 | 범위를 지키려고 미뤘다 (Won't / 다음 단계) |

**배운 점:** "이 기능 없이도 핵심 문제를 풀 수 있나?"라고 물으면 자를 것이 보였다. 자른 기능은 버린 게 아니라 순서를 정한 것이다. 실제로 미뤄 둔 로그인은 첫 조각이 굴러간 뒤에 붙이니 훨씬 수월했다.

## 1-1. 확장: 버전 2(API·DB)와 구글 로그인

| 단계 | 한 것 |
|---|---|
| **버전 2** | 화면은 그대로 두고, Express API 서버와 DB(배포 Supabase, 로컬 SQLite)를 붙였다. 용어는 API로 불러오고, 내 기록은 저장·조회·삭제(CRUD)를 API로 한다. 설명 없이 '마치기'는 화면·서버·DB 세 곳에서 막는다 |
| **배포** | Render(서버+화면 한 주소) + Supabase. 예전 GitHub Pages 주소는 Render로 넘겨 준다 |
| **구글 로그인** | Supabase Auth로 구글 로그인을 붙였다. 로그인하면 휴대폰·PC에서 같은 기록을 보고, 로그인 전에 쓴 기록은 로그인할 때 계정으로 옮긴다. 로그인 없이도 쓸 수 있다 |
| **보안** | 로그인 토큰은 브라우저 코드가 못 읽는 쿠키에만 둔다. 기록 주인을 `device:…` / `user:…`로 나눠 남의 기록을 읽을 수 없게 했다. DB 비밀 키는 Render 환경변수에만 둔다 |
| **공개** | 아무 구글 계정이나 로그인할 수 있도록 Google 앱을 게시했다. 이를 위해 개인정보처리방침 페이지를 만들었다 |

## 2. 어디서 막혔고, 어떻게 풀었나

| 막힌 곳 | 푼 방법 |
|---|---|
| **주제가 계속 커졌다** (투자 → 자동화 → 태그 자동화…) | 퀘스트 기준표(흐름 하나, 클릭으로 확인, 외부 데이터 없이)를 먼저 세우고 후보를 그 기준으로 비교했다 |
| **"그냥 할 일 목록 아냐?"라는 고민** | 차별점을 하나로 정했다: 나의 언어로 설명을 써야만 '마치기'가 된다 |
| **디자인 무드를 두 번 바꿨다** (다크 그린 → 노랑 포스터) | 무드(색·글꼴)와 쓰기 편함(검색·저장·버튼 크기)을 나눠서, 무드만 바꾸고 사용성 원칙은 유지했다 |
| **이름을 네 번 바꿨다** | "친구와 대화하다 나온 말"이라는 기준을 세우니 '아, 그게 뭐더라?'로 정해졌다 |
| **고친 화면이 안 보였다** | 브라우저 캐시 때문이었다. 파일 주소에 `?v=` 버전 번호를 붙여 해결 |
| **휴대폰에서 노란 칸이 세로로 길어졌다** | 화면에 안 보일 때 너비를 0으로 재던 버그. 원인을 찾아 화면 밖에서 재도록 고쳤다 |
| **사파리 뒤로 가기가 안 됐다** | 카드를 열 때 방문 기록을 남기도록(History API) 바꿔 해결 |
| **Render 루트 폴더가 `server/`로 잘못 들어갔다** | 폴더 고르는 목록이 펼쳐진 채로 다른 칸을 누르다 하위 폴더가 골라졌다. 목록을 닫고 다시 `study-terms-app`으로 맞췄다 |
| **배포 설정 중 Render 탭을 실수로 닫았다** | 서비스가 만들어지기 전이라 처음부터 다시 채웠다. 비밀 키 칸만 비워 두는 순서는 같게 |
| **Google 비밀번호(Client Secret)를 복사하지 못하고 저장했다** | 한 번만 보여 주는 값이라 다시 볼 수 없었다. 같은 클라이언트에 비밀번호를 새로 추가해서 해결했다 |
| **테스트 모드라 본인 계정만 로그인됐다** | 앱을 게시하려면 홈페이지와 개인정보처리방침 링크가 필요했다. 개인정보처리방침 페이지를 만들어 배포하고 앱을 게시했다 |
| **DB 표 구조를 바꿔야 했다** (`device_id` → `owner_id`) | 기존 기록을 지우지 않고 옮기는 SQL을 만들고, 로컬 DB도 서버가 켜질 때 자동으로 옮기게 했다. 시험으로 옮기기를 먼저 확인했다 |
| **용어 600개를 어떻게 넣지?** | "실습하다 '이게 뭐지?' 할 실전 용어만, 뜻은 PDF 기반, 겹치면 하나로"라는 기준을 먼저 정하고 144개로 추렸다 |

## 3. 가장 도움이 된 규율

**한 번에 하나만.** 수정 요청을 작게 하나씩 하고, 화면을 직접 보고, 마음에 안 들면 바로 다시 말했다. "세로선 말고 가로선", "1cm만 줄여 줘"처럼 구체적으로 말할수록 결과가 정확했다.

**작동하면 저장(커밋).** 이틀 동안 30번 넘게 커밋했다. 버전 2부터는 `npm test`(시험 10개)를 통과한 뒤에 커밋했다. 덕분에 언제든 되돌릴 수 있다는 안심이 있었다.

## 4. AI와 협업하며 배운 점

- **방법보다 의도를 말하면 된다.** "어떤 기술을 써라"가 아니라 "사용자가 이렇게 느꼈으면 좋겠다"를 말하면, 방법은 AI가 근거와 함께 제안했다.
- **화면은 직접 봐야 한다.** AI가 "됐다"고 해도 캡처로 확인하고 피드백해야 내가 원하는 모양이 됐다.
- **AI가 만든 내용도 검증이 필요하다.** 용어 뜻은 PDF를 근거로 쓰게 했지만, 아직 한 줄씩 원문과 대조하지는 않았다.
- **질문하며 정하는 게 빨랐다.** 바로 만들기보다 "어떤 게 퀘스트에 맞을까?"를 묻고 따져 본 시간이, 나중에 다시 만드는 시간을 줄였다.

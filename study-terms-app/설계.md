# 설계 - 기술 선택과 근거

PRD.md에는 무엇을 만들지만 적고, 어떻게 만들지는 이 문서에 적는다.

## 요구사항에서 나온 조건

- 혼자 쓴다. 로그인이 없다. (PRD Won't 1)
- 새로고침해도 내 설명과 상태가 남아야 한다. (PRD 성공 조건 2)
- 용어 데이터는 미리 정해진 20개로 시작한다.
- 무료로 시작하고 배포한다.

## 후보 비교

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **A. 정적 HTML·CSS·JS + 브라우저 저장(localStorage)** | 서버가 없어 설치·배포가 가장 쉽다. GitHub Pages에 무료로 올라간다. 저장소의 다른 게임 과제와 같은 방식이다 | 저장이 브라우저마다 따로라 다른 기기와 공유되지 않는다 | **선택** |
| B. 정적 화면 + Supabase | 기기를 바꿔도 데이터가 남는다. 다음 단계의 로그인과 바로 이어진다 | 혼자 쓰는 첫 조각에는 과하다. 키 관리와 RLS 설정이 먼저 필요하다 | 다음 단계 (로그인 붙일 때) |
| C. Node.js 서버 + DB (Todo 앱 방식) | 서버 로직을 자유롭게 쓴다 | 서버 배포(Render 등)와 재시작 시 데이터 문제를 챙겨야 한다 | 이번엔 불필요 |

## 선택: A

- **화면:** `index.html`(구조) · `styles.css`(표현) · `app.js`(동작) 세 겹. 빌드 도구 없이 파일을 바로 연다.
- **용어 데이터:** `terms.js`에 배열로 둔다. 파일을 더블클릭해 열어도 동작하도록 JSON 파일을 따로 불러오지 않는다.
- **저장:** 내 설명과 상태만 브라우저 `localStorage`에 저장한다. 용어 데이터 자체는 저장하지 않으므로, 용어를 고쳐도 내 기록은 용어 ID로 이어진다.
- **배포:** GitHub Pages. 주소는 `https://k-im-rose.github.io/aiffel/study-terms-app/`가 된다.

## 알고 가는 한계

- 다른 브라우저나 기기에서 열면 내 기록이 보이지 않는다. 브라우저 데이터를 지우면 기록도 사라진다.
- 이 한계는 로그인 단계에서 Supabase로 옮기며 푼다. 그때 localStorage 기록을 옮겨 담는 방법도 함께 정한다.

## 비밀값

이번 단계에는 API 키나 비밀값이 없다. Supabase를 붙일 때 `.env`와 `.gitignore`를 먼저 설정한다.

## 구조

```
브라우저 (public/)  ──fetch──▶  Express (server/index.js)  ──▶  저장소
  index.html · styles.css · app.js     /api/terms, /api/notes          Supabase(배포) 또는 SQLite(로컬)
```

- **저장소 고르기:** `SUPABASE_URL`과 `SUPABASE_SECRET_KEY`가 있으면 Supabase, 없으면 로컬 SQLite(`study-terms.db`, Node 내장 `node:sqlite`). 그래서 계정 없이도 내 컴퓨터에서 바로 실행·시험할 수 있다.
- **용어 원본:** `data/terms.js`, `data/terms-02-0N.js`. 서버가 켜질 때마다 DB의 `sections`·`terms` 표에 맞춘다(있으면 고치고 없으면 넣기). 새 강의 용어는 파일 하나를 더하고 서버를 다시 켜면 된다.
- **사람 구분:** 브라우저가 처음 열 때 무작위 ID(UUID)를 만들어 `X-Device-Id` 헤더로 보낸다. 구글로 로그인하면 서버가 쿠키의 토큰으로 계정을 확인해 그 계정으로 저장한다. DB에는 `device:<UUID>` / `user:<계정 ID>`처럼 앞말을 붙여 저장해서, 남의 계정 ID를 기기 ID로 보내도 그 계정 기록은 읽을 수 없다.
- **구글 로그인 (Supabase Auth, PKCE):** `/api/auth/google` → 구글 → Supabase → `/api/auth/callback?code=…`. 로그인을 시작한 브라우저만 code를 세션으로 바꿀 수 있도록 PKCE 값을 10분짜리 httpOnly 쿠키에 맡긴다. 세션 토큰도 httpOnly 쿠키에만 두고, 만료되면 서버가 refresh 토큰으로 새로 받는다. 화면 코드는 키·토큰을 전혀 모르고 외부 스크립트도 더하지 않았다.
- **로그인할 때 기록 합치기:** 이 기기의 기록을 계정으로 옮기고 기기 쪽은 지운다. 같은 용어가 계정에도 있으면 계정 쪽을 남긴다 (다른 기기에서 쓴 것을 덮어쓰지 않게).
- **옛 기록 옮기기:** 버전 1에서 브라우저에 남긴 기록은 처음 열 때 한 번 서버로 옮기고 지운다.

## 보안

- **비밀 키는 서버에만:** Supabase 비밀 키는 Render 환경변수에만 둔다. 코드·git·브라우저에는 없다.
- **RLS:** 모든 표에 RLS를 켜고 공개 정책을 만들지 않는다. 브라우저용 공개 키로는 아무것도 못 읽고, 비밀 키를 가진 서버만 접근한다.
- **서버 측 검증:** 화면에서 막아도 서버가 다시 검사한다. 상태는 0·1·2만, 내 설명은 5000자까지, 설명 없이 '마치기'(2) 금지. DB에도 같은 규칙을 제약(check)으로 둔다.
- **오류 메시지:** DB 오류 내용은 서버 로그에만 남기고 화면에는 짧은 말만 보낸다.

## 알고 가는 한계

- 로그인하지 않으면 기록은 "브라우저마다" 따로다. 구글 로그인으로 기기 사이에서 같은 기록을 본다.
- Supabase 프로젝트를 Todo 앱과 같이 쓰므로, 로그인 계정 목록도 두 앱이 같이 쓴다. 기록 표는 서로 다르다.
- Render 무료 서버는 15분 동안 쓰지 않으면 잠든다. 처음 열 때 30초쯤 걸릴 수 있어서, 화면에 "불러오는 중"과 "다시 시도"를 보여 준다.

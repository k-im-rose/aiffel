# Write My Way — 내 생각을 내 문체로

### ▶ [스킬 파일 바로 보기](.claude/skills/write-my-way/SKILL.md) · [코드 저장소](https://github.com/k-im-rose/aiffel/tree/main/my-skills)

생각나는 대로 적은 메모를 **내 문체의 글**로 만들어 주고, 다 쓴 글은 **내 생각은 그대로 두고 표현만** 다듬어 주는 Claude Code 스킬.

모두의연구소 AIFFEL AI 에이전트 3기 과제 "내가 실제로 쓸 스킬 하나 GitHub에 올리기".

## 왜 만들었나 — 불편 → 해결

**배경.** 일하면서 글을 쓸 일이 많았다. 공지, 안내문, 피드백처럼 생각을 글로 전해야 하는 일이 계속 이어지다 보니, 같은 내용도 어떻게 쓰느냐에 따라 다르게 읽힌다는 걸 알게 됐다. 글쓰기를 제대로 배운 적은 없다. 그래서 AI와 함께 글을 고치면서 조금씩 스타일을 만들어 왔다. 그렇게 어느 정도 자리 잡은 스타일을 한 곳에 정리해 두고 싶었다.

**불편.** 그 스타일이 AI 대화 안에만 있었다. 새 대화를 열면 기준이 사라져서 같은 설명을 처음부터 다시 해야 했다.

- "너무 딱딱해", "너무 평범해", "좀 더 담백하게", "그게 하려던 말이 아니야"를 매번 다시 말했다.
- 메모를 주고 글을 부탁하면, 하지 않은 생각과 경험이 들어가 있었다. 원래 알던 것을 새로 깨달은 것처럼 쓰기도 했다.
- 끝에는 명언 같은 한 줄("~에 투자하는 것일지도 모른다")이나 "그게 좋더라" 같은 감성적인 맺음말이 붙었다. 사실과 생각으로 담백하게 쓰는 스타일과는 거리가 멀었다.
- 업무 공지는 "당초", "결정했습니다" 같은 공문서 말투로 바뀌었다.

**해결.** 매번 하던 설명과 수정 요청을 `SKILL.md` 한 장에 적었다. 이제 새 대화에서 "이걸로 글 써 줘", "이 글 다듬어 줘"라고만 하면 AI가 이 스킬을 스스로 꺼내 쓴다. 대화가 바뀌어도 기준은 파일에 남아 있다.

## 무엇을 하나

| 모드 | 언제 | AI가 하는 일 |
|---|---|---|
| **초안 쓰기** (주로 씀) | 메모, 문장 몇 줄을 주고 "이걸로 글 써 줘" | 순서를 짜고, 잇는 문장을 더해 글로 완성. 단 **말하지 않은 경험·생각은 넣지 않음** |
| **다듬기** | 다 쓴 글을 주고 "다듬어 줘", "덜 딱딱하게" | 어색한 곳만 최소로 고침. 이미 자연스러운 문장은 그대로 |

결과는 완성된 글 + 무엇을 왜 바꿨는지 1~3줄. 그래서 AI가 내 생각까지 바꿨는지 바로 확인할 수 있다.

**쓰지 않는 경우**: 주제만 주고 내용까지 지어 달라는 요청, 발표·말하기 대본, 번역.

## 규칙은 어떻게 만들었나

1. **재료 모으기** — 평소 글쓰기를 자주 맡기던 AI(ChatGPT)에게 그동안의 대화를 분석해 달라고 했다. 자주 했던 수정 요청, 좋아한 결과와 싫어한 결과, 글 종류별 말투를 받았다. 문체를 스스로 정의하기는 어려웠는데, 이 분석에서 기준이 나왔다: **'잘 쓴 글'보다 '내 생각이 정확하게 전달되는 글'.**
2. **초안 작성** — 그 분석으로 첫 `SKILL.md`를 썼다. 공개 저장소라 실제 글과 개인적인 사례는 넣지 않고, 예시는 문체만 보여 주는 만든 문장으로 바꿨다.
3. **시험 → 피드백 → 규칙 추가** — 실제로 쓴 글과 메모로 시험했다. 시험은 매번 **이 대화를 모르는 새 Claude Code 세션**에서 돌려, 스킬이 스스로 발동하는지와 결과를 함께 봤다. 마음에 안 드는 곳이 나올 때마다 그 이유를 규칙으로 옮겼다.

| 시험에서 걸린 것 | 그래서 넣은 규칙 |
|---|---|
| 메모를 줬는데 줄만 바꿔 옮김 | 초안 모드는 적극적으로 구조를 짜고 잇는 문장을 더한다 (다듬기는 최소로) |
| "소문에 투자하는 것일지도 모른다" 같은 마무리 | 생각을 더 세게 만들지 않는다. 새 비유, 명언 같은 한 줄로 맺지 않는다 |
| 원래 알던 관점을 몰랐던 것처럼 써 놓음 | 글쓴이를 깎아내리는 가정을 넣지 않는다 |
| 문장을 잇겠다고 "나중에 사진을 보면"처럼 안 한 행동을 더함 | 매끄럽게 잇기 위해서라도 말하지 않은 행동을 넣지 않는다 |
| "나는 그게 좋더라" | 감성보다 생각. "~어서 좋다" 대신 "~을 알 수 있다" |
| "당초", "결정했습니다" | 딱딱한 한자어·공문서 말 대신 말하듯. 업무 공지는 받는 사람을 챙기는 코치처럼 |
| "~면 좋을 것 같다"로 흐리는 권유 | 권할 때는 "~는 건 어때요?"처럼 직접 제안한다 |
| "완전 공감된다"가 차분한 글에서 튐 | 글 전체 톤에 안 맞는 센 구어는 맞춘다 |
| 짧은 문장만 뚝뚝 / 반대로 세 번씩 늘어지는 문장 | 짧게 열고 한 번 이은 문장으로 푼다. 생각이 바뀌는 곳에서 끊는다 |
| 한 문단에 "미국"이 세 번 | 문맥으로 알 수 있는 주어·명사는 반복하지 않는다 |
| 앞에서 한 말을 끝에서 또 요약 | 같은 내용은 한 번만 |

나중에 GitHub에서 인기 있는 글쓰기 스킬 [humanizer](https://github.com/blader/humanizer)를 읽어 보니, 시험하면서 찾은 규칙 상당수("A가 아니라 B다" 대비, 명언 같은 한 줄 마무리, 같은 주어 반복)가 거기서도 'AI가 쓴 티'로 꼽혀 있었다.

## 확인한 결과

새 Claude Code 세션에서 아래처럼 한마디로 시험했다. 모두 `Skill(write-my-way)`가 스스로 발동했다.

| 시험 | 요청 | 결과 |
|---|---|---|
| SNS 글 다듬기 | "이 글 내 문체로 다듬어 줘" | 말버릇("디벨롭", "~거 같다")은 살리고 반복·어색한 표현만 고침 |
| 업무 안내문 다듬기 | "이 글 다듬어 줘" | 최소 수정. `~습니다` 말투, 정보 그대로 |
| 일정 변경 공지 다듬기 | "이 공지 문장 자연스럽게 다듬어 줘" | 긴 한 문장을 "원래 계획 → 받는 분에게 좋은 점 → 그래서" 세 문장으로. 날짜는 그대로 |
| SNS 글 초안 | 메모 + "SNS 글로 짧게 써 줘" | 메모 속 말로 담백하게, 마지막은 "~는 건 어때요?" 제안 |
| 커뮤니티 자기소개 초안 | 상황 설명 + "자기소개 만들어 줘" | 거창하지 않게, 요청대로 "창업 준비"라는 말 없이 |
| 독후감 마지막 문단 | 메모 + "마지막 문단으로 정리해 줘" | 원래 갖고 있던 관점을 살려 일반론 없이 마무리 |
| **발동하지 않아야 할 때** | "AI 공부하는 것에 대한 블로그 글 하나 써 줘" (주제만) | **발동 안 함** ✅ — 스킬 없이 쓴 글에는 하지 않은 경험("몇 달 해 보니")이 지어져 있었다 |

### 실행 기록 — 새 세션에서 한마디로 발동

이 저장소를 연 새 Claude Code 세션(이전 대화 없음, 2026-11-03)에 메모 한 줄만 보냈다. 아래는 그 세션에서 실제로 나온 도구 호출과 답을 그대로 옮긴 것이다.

```text
❯ 이걸로 SNS 글 짧게 써 줘: 요즘 AI랑 글을 쓰면서 내 문체를 정리해 봄. 매번 같은 설명을 반복하는 게 귀찮았음. 그래서 스킬로 만들어 둠

● Skill(write-my-way)
  └ Launching skill: write-my-way

요즘 AI랑 글을 쓰면서 내 문체를 정리해 봄. 쓸 때마다 같은 설명을 반복하다 보니 그게 귀찮았음. 그래서 아예 스킬로 만들어 둠. 이제는 설명 없이도 내 문체로 써 줌.

---
이렇게 썼어요: SNS 글이라 메모에 쓴 `~음` 말투를 그대로 살렸어요. 흐름은 문체 정리 → 반복이 귀찮았던 이유 → 스킬로 만듦 순서예요. 마지막 문장은 스킬로 만든 결과를 풀어 쓰려고 제가 더했어요. 메모에는 없던 내용이니 맞지 않으면 빼고 "그래서 스킬로 만들어 둠."에서 끝내도 돼요.
```

스킬 이름을 부르지 않았는데 description을 보고 스스로 골랐다. 메모의 말투(`~음`)를 살렸고, 메모에 없던 마지막 문장은 직접 더했다고 밝혔다.

## 설치와 사용

**어디서나 쓰기 (추천)** — 글쓰기는 특정 프로젝트와 상관없으니 개인 스킬 폴더에 둔다.

```bash
mkdir -p ~/.claude/skills
cp -r .claude/skills/write-my-way ~/.claude/skills/
```

**한 프로젝트에서만 쓰기** — 그 프로젝트 폴더의 `.claude/skills/write-my-way/SKILL.md`로 복사한다.

복사한 뒤 Claude Code를 다시 켜고 이렇게 말하면 된다.

> 이걸로 글 써 줘: (메모)
>
> 이 글 다듬어 줘: (글)

`/write-my-way`로 직접 불러도 된다.

**다른 사람이 쓴다면** — 규칙은 만든 사람의 문체(담백함, 짧게 열고 한 번 잇는 문장, 감성적인 맺음말 금지, 업무 공지는 코치 말투)에 맞춰져 있다. 자기 문체에 맞게 `SKILL.md`의 "문체 규칙"과 "글의 종류와 어투" 표를 고쳐 쓰면 된다.

# 🍜 냥이의 라면가게

냥이와 함께 손님의 주문대로 라면을 끓이는 3D 요리 게임이다.
어린 시절 즐겨 하던 플래시 게임 **'슈의 라면가게'**에서 아이디어를 얻었다.

- **플레이 주소:** https://k-im-rose.github.io/my-game/nyangi-ramen/
- **저장소:** https://github.com/k-im-rose/my-game
- **대상:** 초등 저학년 (7~9세)
- **조작:** 마우스 클릭 / 터치 / 키보드
- **만든 방법:** 개발 에이전트(Claude Code)와 대화하며 만드는 바이브 코딩

---

## 1. 기획 배경

### 왜 만들었나
라면 끓이기는 아이들도 집에서 한 번쯤 본 익숙한 요리다. 그런데 실제로 라면을 끓이려면 **정해진 순서**를 지키고, **어떻게 만들지 기억**해야 한다.
이 게임은 그 두 가지를 아이들이 놀이로 연습할 수 있도록 기획했다.

### 이 게임으로 기르고 싶은 능력

**① 순서대로 해내는 힘 (절차적 사고)**
라면 한 그릇을 만들려면 `물 붓기 → 불 켜기 → 끓으면 면·스프 → 토핑·맵기 → 알맞게 익으면 서빙` 순서를 지켜야 한다. (토핑끼리의 순서는 자유다.)
- 순서를 건너뛰면 결과가 달라진다. 스프를 빼먹으면 별점이 크게 깎이고, 물이 끓기 전에 면을 넣으면 면이 천천히 익는다.
- 냄비 위에 "물을 부어 주세요", "불을 켜 주세요"처럼 **다음 할 일**이 계속 떠서, 아이가 혼자서도 순서를 익힐 수 있다.
- 하루가 지날수록 토핑이 늘어나 단계가 조금씩 길어진다. 쉬운 순서부터 시작해 점점 긴 순서를 해내도록 설계했다.

**② 주문 기억하기 (작업 기억)**
손님마다 원하는 라면이 다르다. 물 양(적게·보통·많이), 익힘(꼬들꼬들·적당히·푹 익음), 토핑 종류를 **기억하고 그대로 만들어야** 한다.
- 주문서를 보고, 조리하는 동안 그 내용을 머릿속에 담아 둔 채 여러 단계를 진행해야 한다.
- 1일차에는 토핑이 0~2개로 적게 시작하고, 날이 지날수록 기억해야 할 토핑 개수가 늘어난다.
- 주문과 다르게 만들면 손님이 "계란이 빠졌어요", "물이 너무 많아요"처럼 무엇이 틀렸는지 바로 말해 준다. 아이는 자기가 무엇을 잘못 기억했는지 알 수 있다.

> 이 게임은 위 능력을 **연습할 수 있도록 설계**한 것이다. 실제 능력 향상 효과를 실험으로 검증하지는 않았다.

### 7~9세에 맞춘 점
- 하루 영업 시간은 **2분(120초)**이다. 처음엔 3분이었지만, 직접 해 보니 길게 느껴져서 아이들이 집중하기 좋은 2분으로 줄였다.
- 손님이 기다려 주는 시간은 1일차 **45초**이고, 하루마다 3초씩 줄어 최소 32초까지 줄어든다.
- 물 양 정답 범위를 넓히고, 면이 천천히 익게 해서 타이밍을 맞추기 쉽게 했다.
- **글 대신 캐릭터로 시작한다.** 첫 화면에는 긴 설명 없이 라면가게 거리 앞에 선 냥이와 '시작하기'·'사용 방법' 버튼 두 개만 있다.
- **사용 방법은 냥이가 직접 알려 준다.** 냥이가 말풍선으로 한 단계씩(7단계, 맵기 설명 포함) 설명하고, 각 단계마다 실제 버튼·게이지가 움직이는 그림을 보여 준다.
- **실수해도 괜찮게** 만들었다. '버리기'로 처음부터 다시 할 수 있고, 목표를 못 채워도 같은 날을 다시 도전할 수 있다. 다만 토핑은 한 번 넣으면 뺄 수 없어서, 주문을 잘 보고 넣어야 한다.
- 물 붓기는 **버튼을 꾹 누르다가 알맞을 때 손을 떼는** 조작이라 아이들이 직관적으로 할 수 있다.

| **끝나는 조건** | 하루 2분이 지나면 영업 끝. 목표 매출을 넘기면 다음 날로, 못 넘기면 같은 날 다시 도전 |
| **예외 상황** | 손님이 너무 오래 기다리면 화가 나서 떠남 / 손님이 없거나 면을 안 넣었으면 서빙 불가 / 빈 냄비에 불을 켜면 경고 / 물을 너무 많이 부으면 "물이 넘쳐요!" |

## 3. 게임 방법

### 화면 흐름
1. **첫 화면** — 라면가게 거리 앞에서 냥이가 손을 흔든다. 냥이를 누르면 빙그르 돌거나 폴짝 뛰거나 몸을 흔들며 하트가 떠오른다. 귀엽고 통통 튀는 배경음악이 흐르고, 오른쪽 위 종 아이콘으로 소리를 끄고 켤 수 있다. '시작하기'를 누르면 냥이가 가스레인지 앞으로 걸어가며 가게가 열린다.
2. **사용 방법** — 첫 화면의 작은 '사용 방법' 버튼을 누르면 냥이가 말풍선으로 7단계를 하나씩 설명해 준다. 마지막 단계에서 바로 시작할 수 있다.
3. **영업 화면** — 위쪽에 주방, 아래쪽에 조리 버튼이 있다.
4. **영업 끝 화면** — 냥이가 다시 앞으로 나와서 오늘 결과를 말해 준다. 별점, 목표까지 채운 매출 막대, 받은 손님 수가 나오고, 성공하면 '다음 날 영업하기', 아쉬우면 '다시 도전하기' 버튼이 나온다.

### 목표
하루 영업 시간(2분) 안에 **오늘 목표 매출**을 넘기면 성공이다.
목표는 1일차 15,000원에서 시작해 하루마다 3,000원씩 올라간다(2일차 18,000원, 3일차 21,000원). 하루 영업 시간은 매일 2분으로 같다.

### 라면 끓이는 순서
1. **주문서 보기** — 왼쪽 위 주문서에서 물 양, 익힘, 토핑, 맵기를 확인한다.
2. **물 붓기 (꾹 누르기)** — '물 양' 게이지가 **분홍 테두리 칸** 안에 들어오면 손을 뗀다.
3. **불 켜기** — 냄비 위에 '보글보글!'이 뜨면 물이 끓은 것이다.
4. **면·스프 넣기 → 토핑 올리기 → 맵기 맞추기** — 넣는 순서는 자유다. 스프를 빼먹으면 별점이 크게 깎인다!
   - 토핑은 한 번 넣으면 뺄 수 없다.
   - **맵기:** 주문서 왼쪽 위에 '맵기 2단계'처럼 나온다. 맵기 단계만큼 고춧가루를 누른다. 맵기는 0~10단계가 있고, 고춧가루는 10번까지만 눌린다. 누를 때마다 주문서 맵기 옆에 빨간 점이 하나씩 생긴다(다섯 개씩 한 줄).

     | 맵기 | 0단계 | 1단계 | 2단계 | … | 10단계 |
     |---|---|---|---|---|---|
     | 고춧가루 | 안 넣기 | 한 번 | 두 번 | … | 열 번 |
5. **서빙하기** — '익힘' 게이지의 검은 막대가 분홍 칸 안에 있을 때 서빙한다. 냄비 위 글씨가 **초록색**으로 바뀌면 바로 그때다.

### 별점과 돈
| 별점 | 받는 돈 |
|---|---|
| ★★★ | 라면값 전부 |
| ★★☆ | 라면값의 85% |
| ★☆☆ | 라면값의 50% |
| ☆☆☆ | 못 받음 |

라면값은 기본 3,000원에 주문한 토핑 1개마다 500원이 더해진다.

### 이기는 요령
- 손님이 오기 전에 물을 '보통'만큼 붓고 불을 켜 두면 시간이 크게 줄어든다.
- 물이 끓은 뒤 면을 넣고 **꼬들꼬들은 약 3~6초, 적당히는 약 6~9초, 푹 익음은 약 9~11초** 정도 기다린다.
- 주문서의 손님 인내심 막대가 빨개지기 전에 서빙한다.

### 조작키
키보드 자판이 **화면 버튼 배치와 똑같은 모양**이 되도록 왼손 가까이에 모았다. 각 버튼에 해당 키가 작게 적혀 있다.

```
화면                                   키보드
[물 붓기][불 켜기][면 넣기][스프]      →  Q  W  E  R
[고춧가루][계란][파][치즈][떡][만두]   →  A  S  D  F  G  H
[버리기]        [서빙하기]             →  Z      Space
```

| 동작 | 버튼 | 키보드 |
|---|---|---|
| 물 붓기 | 물 붓기 (꾹 누르기) | Q (누르고 있기) |
| 불 켜기/끄기 | 불 켜기 | W |
| 면 넣기 | 면 넣기 | E |
| 스프 넣기 | 스프 | R |
| 토핑 | 고춧가루·계란·파·치즈·떡·만두 | A · S · D · F · G · H |
| 냄비 비우기 | 버리기 | Z |
| 서빙 | 서빙하기 | Space |

한글 입력 상태에서도 그대로 동작한다.

Tab 키로 버튼 사이를 이동해 키보드만으로도 플레이할 수 있다.

### 날마다 열리는 토핑
| 날 | 새 토핑 |
|---|---|
| 1일차 | 계란, 파, 고춧가루(맵기 0~10단계) |
| 2일차 | 치즈 |
| 3일차 | 떡, 만두 |

영업을 시작할 때 냥이가 "맵기는 고춧가루 횟수야! 0단계는 안 넣고, 1단계는 한 번, 10단계는 열 번!"처럼 그날 알아 둘 것을 짧게 알려 준다.

## 4. 적용한 게임 전략

1. **난이도 곡선** — 1일차부터 맵기(고춧가루 횟수)를 기억해야 하고, 날마다 토핑 종류와 한 주문의 토핑 개수가 늘어나며, 손님이 기다려 주는 시간은 줄어든다. 목표 금액은 처음 하는 사람도 해낼 수 있게 하루 3,000원씩만 올라간다.
2. **눈에 보이는 목표** — 게이지 위 분홍 칸으로 정답 범위를 보여 주고, 딱 맞는 순간엔 초록색으로 알려 준다. 고춧가루를 누른 횟수는 주문서 맵기 옆 빨간 점으로 보여 준다.
3. **즉각적인 보상** — 서빙하자마자 별점, 손님의 한마디, 돈이 오르는 효과, 냥이의 기쁜 동작, 효과음이 나온다.
4. **다음 할 일 안내** — 냄비 위에 지금 해야 할 일이 계속 표시된다.
5. **실수해도 괜찮게, 하지만 신중하게** — 버리기와 같은 날 재도전으로 실패 부담을 줄였다. 토핑은 한 번 넣으면 뺄 수 없게 해서 주문을 잘 기억하고 넣도록 했다.
6. **빠를수록 더 많은 손님** — 손님이 금방금방 오가서, 빨리 끓일수록 하루에 더 많은 손님을 받을 수 있다. '미리 물 끓여 두기' 같은 요령이 생긴다. 아이들에게 낯선 '팁' 개념은 넣지 않았다.
7. **눈과 귀로 느끼는 보상** — 돈을 받으면 동전이 짤랑 소리와 함께 돼지 저금통에 들어가고, 영업 끝에 성공하면 냥이가 방방 뛰며 "와~" 함성이, 실패하면 우는 소리가 난다.
8. **귀여운 분위기** — 분홍 하늘과 구름, 별과 하트, 동물 손님, 알록달록한 상점가로 아이들이 좋아할 분위기를 만들었다.
9. **캐릭터가 이끄는 안내** — 첫 화면, 사용 방법, 영업 끝 화면 모두 냥이가 화면 가운데에서 말하는 형식이라 글을 많이 읽지 않아도 흐름을 따라갈 수 있다.

## 5. 기술 구성

```
my-game/
├── nyangi-ramen/
│   ├── index.html   # 화면 구조 (주문서, 게이지, 버튼, 시작·결과 화면)
│   ├── styles.css   # 디자인 (색, 글꼴, 배치, 모바일 대응)
│   ├── script.js    # 3D 장면과 게임 규칙 (조리 상태, 손님, 별점, 하루 진행)
│   └── favicon.png 외 아이콘 2개  # 브라우저 탭·홈 화면 아이콘 (게임 속 3D 냥이 얼굴)
├── parkour-runner/  # 도시 파쿠르 러너 (별도 게임)
└── README.md
```

- **HTML · CSS · JavaScript** 세 파일로 나누어, 화면(구조)·모양(표현)·규칙(동작)을 따로 고칠 수 있게 했다.
- **Three.js**로 3D 장면을 그렸다. 냥이와 손님은 이미지 파일 없이 공·원뿔 같은 기본 도형을 조립해서 만들었다.
- 글꼴은 Google Fonts의 **Jua**(제목·버튼)와 **Gowun Dodum**(본문)을 썼다.
- 효과음과 배경음악은 파일 없이 브라우저의 Web Audio로 직접 만들었다. 배경음악은 이 게임을 위해 새로 지은 귀엽고 통통 튀는 짧은 곡(쿵짝 리듬 + 짧게 튕기는 멜로디)이라 저작권 걱정이 없다.
- 휴대폰에서는 화면을 처음 터치할 때 소리를 켜고, 아이폰 무음 스위치가 켜져 있어도 게임 소리가 나도록 했다. 배포할 때마다 휴대폰도 새 파일을 받아 오도록 script.js·styles.css 주소에 버전 번호를 붙였다.

## 7. 회고

### 어떻게 진행했나
- **왜 이 게임인가:** '슈의 라면가게'는 어릴 때 재밌게 했던 게임이다. 난이도가 있어서 적당히 어려웠고, 그래서 더 재밌었다.
- **왜 이 캐릭터인가:** 내가 좋아하는 고양이 캐릭터로 만들고 싶었다. 대중적으로 사랑받는 캐릭터라서, 어린이 대상 게임이지만 어른들도 한번 해 보고 싶어질 것 같았다.
- **어떻게 만들었나:** 처음에는 "슈의 라면가게처럼, 이 캐릭터로 3D로 만들어 줘"라고 한 줄로 시작했다. 그다음부터는 직접 플레이해 보고 마음에 안 드는 부분을 하나씩 말로 고쳐 나갔다(6장 '만든 과정' 표의 1~13회차).

### 결과는 어땠나
- 내가 고른 게임(라면 끓이기)의 규칙이 실제로 돌아가는 3D 웹 게임을 완성했고, GitHub Pages로 배포했다.
- 시작 화면 → 사용 방법 → 하루 영업 → 결과 화면 → 다음 날/다시 도전까지 한 바퀴가 동작한다.
- 컴퓨터와 휴대폰 크기 화면 모두에서 플레이할 수 있다.

**처음 플레이해 봤을 때**
- 처음 나온 캐릭터를 보고 '보급형 같다'고 느꼈다. 유명한 캐릭터 사진을 예시로 넣었는데도 똑같이 만드는 건 쉽지 않았다.
- 그래서 "어떤 식으로 대화를 해야 원하는 모습으로 바꿔 나갈 수 있을까?"를 고민하게 됐다. "보급형 같아" → "얼굴이 여전히 달라" + 사진 한 장 더 보내기처럼, 무엇이 다른지 짚어 주고 참고 자료를 더 줄수록 점점 가까워졌다.
- 일단 "만들어 줘"로 시작한 뒤 디테일을 조금씩 고쳐 나가는 재미가 있었다. **AI 개발은 이렇게 하는 거구나** 싶었다.

### 아쉬웠던 점
- **캐릭터와 전반적인 디자인이 아직 보급형 느낌이다.** 기본 도형을 조립해서 만든 3D라서 원본 사진만큼 매끈하고 고급스럽지는 않다.
- **라면 끓이는 소리가 없어서 현실감이 부족했다.** → 회고를 쓰다가 직접 요청해서 물 붓는 소리, 가스 불 소리, 보글보글 끓는 소리를 추가했다.
- **규칙을 내가 먼저 적지 않았다.** 수업에서는 PRD(보이는 것·상태·규칙)를 먼저 쓰고 AI에게 시키라고 했는데, 나는 "슈의 라면가게처럼"이라고만 요청했다. 그래서 하루 100초, 끓는 시간 같은 숫자를 AI가 임의로 정했고, 직접 플레이해 보고 나서야 너무 짧거나 길다는 것을 알았다.
- **대상 연령을 처음에 정하지 않았다.** 중간에 어린이용으로 방향을 바꾸면서 시간·난이도를 다시 조정해야 했다. 처음부터 "누가 하는 게임인지" 정했다면 한 번에 맞출 수 있었을 것이다.
- **AI 혼자서는 '재미'를 판단하지 못했다.** AI는 버튼이 눌리는지, 오류가 없는지는 확인했지만, 기다리는 시간이 지루한지는 내가 직접 해 봐야 알 수 있었다.
- **시간이 더 있었다면** 디자인과 조명을 더 디테일하게 지시해 보고 싶다.

### 느낀 점
- 말 한마디로 이렇게 쉽게 게임이 만들어지는 게 신기했다.
- **내가 지시를 잘할수록 퀄리티와 디테일이 좋아진다**는 것을 직접 경험했다.
- 짧은 시간 안에 이만큼 만들 수 있는 걸 보고, 세상이 참 좋아졌구나 싶었다.
- 만드는 것 자체가 쉬워졌으니, 앞으로는 **퀄리티가 꽤 큰 차별점**이 될 것 같다.

### 마무리 3문장
1. **내 게임을 웹 링크로 처음 열어 봤을 때, 내 컴퓨터에서 열 때와 무엇이 달랐나?**
   예산을 적게 쓴 3D 같은 느낌이었지만, 링크로 열리는 진짜 게임을 보니 좀 더 제대로 다듬으면 재밌게 만들 수 있겠다는 생각이 들었다.
2. **배포 과정에서 AI가 멈추고 나에게 넘긴 단계는 무엇이었고, 왜 사람이 해야 했을까?**
   GitHub 로그인(브라우저에서 코드 입력 후 승인)과 공개 저장소에 올려도 되는지 허락하는 단계였다. **개인 정보 보호, 해킹 방지, 저작권 문제** 때문에 사람이 직접 해야 한다고 생각한다. 내 계정에 들어가는 일과 누구나 볼 수 있게 공개하는 일은 내가 책임지고 결정해야 한다.
3. **이 게임에 딱 한 가지만 더한다면?**
   **테이블을 여러 개 놓고 손님을 동시에 여러 명 받는 기능.** 난이도도 올라가고 더 재밌을 것 같다. 여러 주문을 한꺼번에 기억해야 해서, 이 게임이 기르려는 '주문 기억하기(작업 기억)' 연습에도 잘 맞는다.
